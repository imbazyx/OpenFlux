# OpenFlux для Windows

Клиент под Windows 10–11. Интерфейс тот же, что на телефоне: он лежит в
общем модуле `shared`, а здесь только окно и то, что различается между
платформами.

Всё, что касается Windows-клиента, в этом каталоге. В сборке он подключён
одной строкой в `settings.gradle.kts`.

## Почему не Windows 7

Проверено, а не предположено.

| | |
|---|---|
| Go | Win7 держит только **go1.20.14**; начиная с 1.21 нужен Win10 ([release notes](https://go.dev/doc/go1.21)) |
| Compose Multiplatform | требует JDK 21, а Skiko тянет нативные библиотеки под Win10+ |
| CEF (встроенный браузер) | Chromium прекратил поддержку Win7 |

Ядро на Go под Win7 собрать можно, а вот оболочка — нет: она сделана на
Compose, и понижение версии тулчейна не помогает. Значит для Win7 был бы
нужен второй интерфейс, на Swing или Win32, и две расходящиеся кодовые базы.

**Windows XP** не поддерживается и не может: Go отказался от неё в 1.11
([release notes](https://go.dev/doc/go1.11)), последняя совместимая JVM —
Oracle Java 8u141, и та же сборка режет SHA-1-сертификаты, то есть ломает и
HTTPS.

## Сборка

Ядро — Go, собирается отдельно:

```bash
bash scripts/build-pc-core.sh
```

Приложение:

```bash
./gradlew :OpenFluxPC:createDistributable
```

Готовое приложение: `OpenFluxPC/build/compose/binaries/main/app/OpenFlux/`.
Windows-лаунчер `.exe` и установщик `.msi` собираются **на Windows**:
`jpackage` не умеет делать Windows-пакет из другой системы.

Собирать из двух систем в один каталог нельзя: выход Compose-Desktop не
разделен по ОС, и вторая сборка смешивает jar-файлы с первой — приложение
падает при запуске с `UnsatisfiedLinkError`, хотя сборка зелёная.

Версия — та же, что у телефона, одним свойством:
`./gradlew -PappVersion=2.0.0 :OpenFluxPC:createDistributable`.

## Устройство

| Файл | Зачем |
|---|---|
| `src/main/kotlin/io/openflux/pc/Main.kt` | окно. Больше здесь ничего нет и быть не должно |
| `build.gradle.kts` | сборка, упаковка ядра рядом с приложением |
| `resources/windows/` | ядро. Сборка, не исходник: в `.gitignore` |

Ядро кладётся в `resources/` рядом с приложением. `CoreBinary` читает
`compose.application.resources.dir` — так он и находит бинарник. Без этого
приложение открылось бы нормально, а туннель не поднялся бы: об отсутствии
ядра первым узнаёшь при первом подключении, а не при запуске.
