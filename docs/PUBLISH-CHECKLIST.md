# Чек-лист публикации (локальная подготовка)

> Этот файл — рабочая заметка, а не часть релиза. Перед публикацией на GitHub
> его можно удалить, а заполненные ниже пункты закрыть.

## Что решено

- **Версия релиза: 1.2.0** (совпадает с собранным и подписанным APK,
  `versionCode` 10200). Не 2.0.0 из старого CHANGELOG.
- **Аккаунт GitHub: будет назван позже.** Все ссылки, которые сейчас указывают
  на `p1neappleXpress`, помечены заглушкой `REPLACE_WITH_GITHUB_ACCOUNT`.

## Секреты — проверено, утечек нет

- Пароли keystore читаются из переменных окружения (`ANDROID_KEYSTORE_PASSWORD`,
  `ANDROID_KEY_PASSWORD`), в коде их нет.
- Keystore не в репозитории: генерируется в `$HOME/build/openflux-local.jks`,
  сборка передаёт пароль через `-storepass:env` (вне списка процессов).
- IP/хосты exit-нод и отпечатки сертификатов в индекс не попали.
- `dist/` (пять APK, >100 МБ) в `.gitignore`.

## Что нужно сделать перед публикацией (когда будет аккаунт)

1. **Создать/склонировать свои репозитории** для двух подмодулей:
   - `OpenFlux` (ядро) — с коммитом `5e714cd`;
   - `OpenFluxClientShared` (`shared/`) — с коммитом `ba86d07`.
   Без них форк с `--recurse-submodules` упадёт: эти коммиты есть только локально.
2. Заменить `REPLACE_WITH_GITHUB_ACCOUNT` в:
   - `.gitmodules` (2 URL);
   - `README.md` (ссылки на ядро и общий код);
   - `androidApp/.../AndroidPlatformServices.kt` (`RELEASE_REPO`).
3. Задать секреты в настройках репозитория (Actions → Secrets) для релизов:
   `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`,
   `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`.
   **Локальный keystore — личный, для официальных сборок нужен свой.**
4. Проверить, что форк идёт от нужного upstream: в README оставить ссылку на
   оригинал и в «Credits» отметить авторство.

## Теги

- `v1.2.0` — релизный коммит (создаётся на текущем `f3d6d58`).
- Старый `v2.0.0` указывал на **первый** коммит (`3515008`), то есть под тегом
  не было ни одной правки приложения. Это вводит в заблуждение, поэтому перед
  публикацией его нужно либо переставить на релизный коммит, либо удалить —
  решать владельцу. Сам тег не опубликован, пушите только `v1.2.0`.
